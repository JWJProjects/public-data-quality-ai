# 合流｜需求、交付與驗收基線

版本 1.0 · 自行設計的需求方案展示，非招標原文。沒有委託機關或實際需求方，不代表承接承諾或機關驗收。本文區分**合成演練已證明**與**正式導入待確認**；若未來正式導入，場域規則、門檻、工期與權責須由實際採用方核定。

## 1. 需求與責任

來源承辦角色提供經授權的匯出及欄位定義；整合承辦人對應與檢核；業務覆核人只處理模型待查，不能在展示內放行規則錯誤；驗收人按輸入、報告及輸出對帳。若有資料錯誤，由來源承辦更正後重新匯入。上述為建議角色，不表示原型已能識別使用者、分權或留存永久查證軌跡。

| 需求 | 交付項 | 可配置或固定行為 | 驗收案例 |
| --- | --- | --- | --- |
| **REQ-01 資料整合** | D1 匯入、映射與來源追溯 | 每來源選自己的欄位，預先對應常見欄名；支援 UTF-8 CSV／JSON 物件陣列。每檔 2 MB、40 欄、最多 12 個來源、批次上限 10,000 筆。第一個實際匯入替換預載批次 | AC-01、02、06 |
| **REQ-02 品質規則** | D2 規則檢核與失敗理由 | 日期、必填、非負整數天數與有限非負金額、已知狀態固定啟用；狀態正規化、跨來源去重可開關。去重採先到者，不自動合併、不推定較新者正確 | AC-02、03、06 |
| **REQ-03 異常待查** | D3 類別基線與覆核紀錄 | 異常提示可開關、距離門檻 1.0–8.0。模型只提示，不當作定性判斷；規則錯誤不得透過人工放行。改映射／規則重設放行 | AC-01、04、08 |
| **REQ-04 交付與交換** | D4 標準檔、內部檢核報告、合成摘要 | 標準 CSV／JSON 只含合格資料、附來源序號及來源內資料列；內部報告含映射／規則／處理狀態。跨工具摘要限純內建合成批次，手動下載及匯入 | AC-02、05、07 |
| **REQ-05 執行與交接** | D5 本機執行、範例、測試及畫面 | 不需外部依賴、API key 或帳號；無後端、無寫回正式來源、無永久稽核。瀏覽器工作階段記憶體，重新整理清除 | AC-01、06、09 |

展示七欄：編號、行政區、類別、日期、處理天數、金額及狀態。擴充新場域可新增 `data.js` 的欄位契約、類別、來源欄名和合法基線，匯入層接收 `{headers, rows}`。既有 `engine.js` 負責解析、規則、資料擬合與計分；`app.js` 負責操作與匯出。現階段不能任意調整欄型或接上自動同步，正式介接應先確認版本、金額精度及失敗重送策略。

| **AC-05** | 下載標準 CSV／JSON 與檢核報告 | CSV 中的公式型文字以防護前綴處理；標準檔有來源序號及資料列；報告無資料列原始值，仍含映射 | Node 檢 CSV 防護、Chrome 實下載標準 JSON；完整報告可手動核對 |
| **AC-06** | 以重複欄名、未閉合引號、少欄或巢狀 JSON 做失敗樣本 | 解析拒絕，不生成新整併結果；前端提示錯誤，保留前批次 | Node 檢解析拒絕；前端錯誤回復流程可重跑，未列為此次 Chrome 實測 |
| **AC-07** | 匯出[內建合成摘要](../examples/qa-evidence.json)後，在[案跡](https://github.com/JWJProjects/report-evidence-ai)匯入；再以自有匯入批次查看交換按鈕 | 案跡讀到 18／13／1／4；不含原始資料、欄名、檔名或案件編號。自有批次不可交換 | 兩套實際瀏覽器全流程 |
| **AC-08** | 固定種子重建樣本；輸入罕見或無基線類別 | 同類中位基線的測試點距離為零；參考少於 8 筆不評分，無基線不能視為模型認可 | Node |
| **AC-09** | 在 390 px 視窗載入，切換導覽，確認表格可區內捲動 | 總覽無全頁水平溢位；有[行動版畫面](assets/05-mobile.jpg) | Chrome 390 px 內嵌視口及畫面確認 |

重跑：`npm test`。選用的 `tests/browser-qa.py` 需要 Python Playwright 與 Chromium；開發環境的殼層 Chromium 建 socket 受限，本次瀏覽器互動以內部 Chrome 實測，未將選用腳本列為通過。

## 3. 正式導入的里程碑與責任

| 里程碑 | 責任與應交付 | 尚未包含於示範 |
| --- | --- | --- |
| M1 資料盤點與設計確認 | 資料權責人與執行方核定資料字典、合法來源、樣本與欄位版本、期望誤差及關鍵通知流程 | 真實樣本、個資分類與合法使用確認、正式介接權限 |
| M2 測試環境與驗收演練 | 整合與測試團隊交付介接規格、錯誤回復、對帳產物；業務覆核人確認規則、模型門檻、拒絕與撤回流程 | API／SFTP、角色權限、永久日誌、正式容量與相容性、未知類別處理 |
| M3 上線與交接 | 正式採用方指定驗收人、系統維運方核驗發布／回復、備份還原、監控告警及教育手冊 | 資安與備援實測、正式驗收、SLA、上線及保固 |

**資安底線：** 應先釐清資料最小化、匯出範圍、保留期限與驗收資料身分；展示版只用合成案例，不接正式系統或個人資料，不做權限、資安或法規合規的保證。原型的本機處理措施不能取代正式上線安全審查。
